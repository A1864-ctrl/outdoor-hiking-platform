## 三、清洗规则

### 3.1 城市名口径归一

旧数据里景点用短名、路线用全称，旧代码靠 `norm_city()` 截字符串硬凑：

- 景点：`深圳`、`广州`、`桂林`
- 路线：`深圳市大鹏新区`、`广州市从化区`、`桂林市阳朔县`

**新做法**：在导入脚本里统一剥离"市/区/县/自治州"后缀取地级市名，写入 `region` 表并建立唯一索引
`(province, city)`。后续所有查询只走 `region_id`，运行时不再需要字符串匹配。

### 3.2 跨年季节区间

`best_season` 存在 `10-5月` 这种跨年区间。用 `start ≤ month ≤ end` 判断会永远匹配不上。

**约定**：`season_start > season_end` 表示跨年（10 月到次年 5 月）。
判断逻辑写成：

```python
def in_season(month, start, end):
    if start is None or end is None:
        return True
    if start <= end:
        return start <= month <= end
    return month >= start or month <= end   # 跨年
```

### 3.3 路线类型归一（25 种 → 6 类）

原数据 `type` 有 25 种取值，且同义重复。归类结果：

| 归入 | 原始取值（含重复写法） |
|---|---|
| 山岳 | 山岳、登山、山峰、高山、山地、丹霞、丹霞地貌 |
| 海岸线 | 海岸线、海滨、海岛徒步、沙滩 |
| 溪谷 | 溪谷、峡谷、溯溪、瀑布 |
| 古道 | 古道、驿道、石板路、历史步道 |
| 环湖 | 环湖、湖畔、水库 |
| 城市郊野 | 郊野、城市公园、绿道、田园、乡村、茶园 |

映射表需在论文附录给出，作为数据清洗过程的证据。

### 3.4 必须删除的假数据

旧代码里 `gen_track()` 会为缺少真实轨迹的路线**反推并合成**一条演示曲线。
这类数据进入毕业设计属于学术不端，已在迁移中排除：**只保留 `data/tracks/` 下实际存在的 34 个文件**，
没有轨迹的路线 `track_file` 置 NULL，页面上显示"暂无轨迹"。

## 四、需要人工补录的字段

原数据在"内容充分度"上有缺口，任务书要求的字段填不满：

| 表 | 缺失字段 | 建议补齐范围 |
|---|---|---|
| `attraction` | `address`、`open_time`、`tips` | 优先补热度前 30 条 |
| `hiking_route` | `transport`、`supply`、`safety` | 优先补热度前 20 条 |

补齐依据以官方景区公告、地方政府文旅页面为准，逐条注明来源，避免编造。
